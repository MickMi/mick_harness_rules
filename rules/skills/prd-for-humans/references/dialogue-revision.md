# Revision and sample-conflict examples

These are behavioral acceptance examples, not evidence of a model run.

## Preserve an approved draft

The user has approved a task-search PRD: search registered tasks by title; changing a filter updates the results; clearing restores all tasks. They say: “结构很好，第三部分用图文表格写清字段，其他不动。”

Revise only scene detail and affected visual references. Keep the approved scope and headings. Explain the search input, available filter choices, results, and clear action in a compact table. Reuse a supplied image or say that it is missing. Do not invent export, bulk deletion, a new permission model, or a new design. Do not restart discovery or automatically update the user's Profile.

If the user next says “再短一点，但字段别删”, reduce duplicated explanation rather than deleting field meanings and action results. Return the revision and a short account of what changed.

## Resolve conflicting historical examples

A user asks to learn from three historical drafts. Two are revisions of the same feature, with different release scopes; one is an unrelated AI-generated draft with unknown approval. An old memory says to always add an evaluation appendix. The user's current instruction says the PRD is for human review and has no default testing appendix.

Group the two revisions as one sample family. Do not count the third draft as an approved example. Apply the current writing instruction without asking it again; exclude the obsolete appendix rule. Learn useful scene/field exposition, not the old feature scope. If this feature is being rewritten and the scope difference matters, ask which scope is confirmed. Do not merge conflicting versions or assume the highest version number is authoritative.

## Keep a discussion conversational

The user says: “先别写，我想看看用户会从哪里进来。” Discuss alternative entry points and their effect on the experience; do not create a final PRD. When they later ask “信息够了吗，来吧” and the important choices are resolved, draft directly without another outline-approval round.
