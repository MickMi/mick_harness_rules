# Harness 项目操作中心

## 背景与目标

用户已经能在统一工作台查看多个项目，但更新 Harness、注入项目和修复 Agent 接入仍要回到终端，过程不透明。本需求让用户在首页看懂可执行操作、影响范围和最终结果。

## 核心体验

用户选择一个项目和操作后，先看到会改变什么、是否需要确认以及能否恢复。执行期间能看到真实进度；结束后能区分成功、失败和部分完成，并获得明确的后续动作。

## 本期范围

只开放 Harness 更新、项目注入或升级、Agent 接入修复三类白名单操作。任何未识别的操作都不能从工作台发起。

## 分期

### 0.18.0：可控操作闭环

先证明三类白名单操作都能完成预检、确认、执行和结果反馈，失败后可以安全重试。

### 后续版本：组织效率

在真实使用数据证明操作闭环稳定后，再考虑批量项目升级和建议式维护，不在本期提前开放。

## 验收

用户不理解 Git 或命令行也能判断操作对象、风险和结果；刷新页面后仍能找到最近一次操作；失败不会留下无法识别的中间状态。
