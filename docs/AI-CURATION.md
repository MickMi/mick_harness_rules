## v0.26.0 · 2026-09-17 · DeepSeek 开发预览

入口：[6426 → 设置 → AI 整理助手](http://127.0.0.1:6426/?view=settings&focus=ai)。本阶段不发布、不改变 6425。

### 使用路径

1. 保存 DeepSeek 官方地址、模型和 API Key。密钥留空保留原值，移除按钮只清除本机保存的密钥。
2. 点击“测试连接”。使用合成问候检验实际返回，不发送项目资料；仍可能产生少量费用。
3. 在“整理经验”选择项目，可展开“补充一句你的要求”，直接点击“预览内容”。反馈在预览时保存在本机，与新增或变化的项目摘要、少量相关规范一起供你确认；无需单独保存、管理反馈。预览不发送资料。
4. 展开检查实际发送数据，确认后将所选项目的全部新增记录一次发送。不按条数或摘要长度分批，不截断摘要；旧的每批 20 条配置不再生效。系统尝试去掉常见凭据、邮箱、链接及本机用户路径，但不能保证所有业务信息均已脱敏。
5. 阅读行为准则建议：区分新增、修订、落实已有准则，默认显示以后怎么做、适用范围与如何检查；对照与依据折叠。模型直接写 Markdown，记录使用 `[R1]`、规范摘录使用 `[K1]` 等短引用，来源可展开核对。项目复盘单独标记，不进入全局记忆。
6. 每条结果是独立卡片，在右上角“编辑”，可保存或取消。项目复盘可勾选“保留”，保存修改后刷新可继续；自动查询不会覆盖编辑或收起正在操作的卡片。未保存修改仍需先手动保存，直接关闭页面会丢失。
7. 项目复盘核实后“保存到项目记忆”，仅写该项目的试用记忆，不进入全局 Brain。完整建议在卡头“采纳建议”，核实后在同一卡片查看执行说明、记录落实及人工复验；不写记忆、不自动修改规则，也不调用模型。
8. 如旧报告仍在复述问题，点击“重新整理”。保留原报告与人工编辑，预览原报告来源的当前摘要（不发送报告编辑，不附加其他新记录），再次确认后生成一份新报告，会产生新的模型用量。来源已撤回则拒绝，来源已更正须重新预览；不通过清空已处理标记来批量重发。

### v0.26.0 · 2026-10-08 · 同一建议从采纳到复验

本节取代历史阶段中的独立反馈管理和待评估队列动线。用户始终操作同一条建议：核实并采纳 → 交给开发落实 → 记录依据 → 人工复验。执行说明包含行为、范围、对照和最小验证；不执行模型给出的指令，不自动发布。采纳后的正文保留审核快照，其他段落编辑不制造重复建议。

“记录落实”要求实际改动文件、应用范围、问题基线与可回查的验证结果；“记录复验”要求结论、同范围的问题次数与依据。以上均明确是人工记录，不冒充文件存在检查、自动测试或宿主加载证明。复验无改善/变差时继续留在同一建议中跟进，不新建工单；历史复验记录保留。自动检测加载与效果、正式发布、合并退役旧准则仍未接入。

建议复用既有 Harness 改进状态与提案文件，隔离在 `ai-curation-dev/harness-improvements/`；通过线程隔离的显式目录访问，不切换整个服务的状态配置。新采纳不再写一份平行队列。旧队列保留，只在用户明确重新核对并采纳后衔接；没有来源或来源变化时不得静默升级。旧报告正文、反馈历史、密钥和正式 Brain 不被迁移或覆盖。

补充输入按项目保留草稿；预览后刷新可以找回尚未整理的反馈，外发仍需独立确认。清空当前待整理反馈后重新预览即撤回该来源；历史反馈仍可在发送预览及原报告来源中核对，不再占据独立管理模块。

### v0.26.0 · 2026-09-22 · 行为准则变更，而非复盘扩写

本节取代以下历史阶段中的旧报告目标，旧结果不自动改写。

- 新增准则：在已检索材料中未找到对应规范，仍标记待核对，不能宣称全库不存在。
- 修订准则：引用现有规范，明确需要补充或替换哪里、在哪些场景生效。
- 落实已有准则：已有约束充分覆盖，不重复新增；补检查或执行流程。提交时不能选择“行为规则”。
- 项目复盘：保留在对应项目；概览和待观察不是可沉淀的准则，也不作为记忆选择项。

每条准则用一至两句回答“以后必须/不得做什么”，去掉项目名、日期、调试经过后仍能指导行动。卡片另列适用范围和最小检查，证据与对照折叠。队列把准则、范围、检查与来源分开存储，队列不代表规则生效。UI 标准只建议在 UI 任务按需使用，不修改现有加载器、不新增常驻上下文。

规范对照先读取所选已登记项目的固定规范文件 `AGENTS.md`、`.harness/rules/core.md`，再参考服务版本的 core、extended、工作台设计参考，以及配置 Brain 的 global/preferences.md、global/collaboration-style.md。项目文件只能解析到该项目或服务端已知共享 Harness 目录，支持受管符号链接；记录和模型不能指定读取路径。不遍历项目，不读取 plan、原始会话、gotchas、sessions；排除代码块、带日期的日志、合并记录及其尾部。本地关键词检索最多 12 条、正文共 6000 字符，完整展示被选摘录，同分相同内容优先保留项目来源。该上限只控制规范背景，不拆分、不截断项目输入记录。未检索到不代表没有，也不证明规范已在目标项目实际加载；工作台专属视觉规格不能推广成所有项目的强制风格。

发送前明确展示记录与规范都会发送给 DeepSeek。连接、记录或相关规范发生变化时，旧预览失效；发送只使用用户确认的快照，不自动追加材料。提交建议时再次核对来源及规范是否改变。规范引用未知、行为段落不完整或原文重复新增会阻止提交，但不丢弃模型正文；语义是否合理仍由人评估，自动检查不冒充语义质量通过。

用户明确表达的标准可直接成为待审候选，不要求必须多次出错。单次现象不能证明普遍技术根因；未经验证的推断留待观察。旧报告须用户点击“重新整理”、检查新增对照材料并再次确认外发，才能生成新版建议；不自动产生费用或清理 global。

### v0.26.0 · 2026-09-23 · 将明确反馈纳入整理输入

选择项目后，输入“哪里不对、希望怎样”，保存只写开发沙盒的 `feedback.json`，不调用模型、不写 Brain。没有历史摘要的已登记项目也可补充；同一项目重复保存相同反馈不会制造多条证据。

预览直接显示将发送的用户反馈全文，与活动摘要区分。反馈的关键内容优先参与已有准则检索；仍需用户检查记录、规范摘录并明确同意外发。已保存反馈变化使旧预览失效，提交候选时也重新核对来源。用户陈述可表达偏好，不证明技术根因或修复已通过；不自动升格成全局规则。旧报告“重新整理”仍只使用原报告来源，不悄悄加入新反馈；要纳入新反馈，应从上方“预览内容”进入。

NARC 日常 `swift test` 现包含按钮源码保护测试；CI 复用同一入口，已有 Python 准备步骤提前到 Swift 测试前。不安装 App、不增加常驻上下文。真实窗口与模型产出的建议质量仍需单独验收。

### v0.26.0 · 2026-09-22 · 从项目复盘分离可执行的改进建议

每日上限是工作台的费用保护，默认 20、可在“调整上限”修改为 1–100，并非模型供应商限制。用户已选择保留；修改上限不再让已通过的连接测试失效，改密钥或模型仍须重新测试。

新报告优先回答“建议 Harness 增加、修改或删除什么、为什么、如何验证”。没有读取当前 Harness 规则时必须标明待核对，不能臆造现有缺陷或文件路径。每条建议独立成卡，用短段落说明具体行为、来源、边界、落点和验证；不以长篇功能和进度复盘替代建议。

卡片分三类：完整格式的改进建议、待补充建议、项目复盘。分类只用于操作分流，不证明建议真实或可通用。提交改进队列要求完整说明、有效引用、来源未变化、修订一致、用户核实与选择方向；重复提交同一修订不重复入队。旧复盘保留原文，不自动升格；可重新预览原记录、再次确认后生成新建议。

项目复盘只写 `brain/projects/<项目>/learnings.md`，改进候选只在开发队列中待评估；两者均不写 global Brain、不自动变更 Harness。既有已保存内容不自动迁移或删除。

### v0.26.0 · 2026-09-17 · 启示的质量标准

报告目标是“下次怎么做得更好”，不是问题清单、进度汇总或调试过程。每条启示应独立包含以下内容：

| 内容 | 需要回答 |
|---|---|
| 下次怎么做 | 什么场景触发、做什么动作、希望出现什么结果？ |
| 证据与可信度 | 来源实际证明了什么？是已验证经验，还是待验证建议？ |
| 适用边界 | 适用与不适用条件是什么？有无反例、一次性因素或未验证处？ |
| 建议落点 | 优先检查脚本，其次 Skill 或流程；仅适用当前项目的知识留在项目内。为什么这样选择？ |
| 如何验证 | 用什么最小检查或前后对比观察效果？不编造收益、次数或基线。 |

同一任务的多个阶段不是多次独立复发；没有充分证据允许“暂无可沉淀启示”。不强凑条数，不把一次故障升级为永久规则，也可提出减少冗余流程。形状检查仅提示缺少哪些说明，不能验证模型结论是否正确；未按格式返回时仍保留原文供审阅，不重新引入整份报告拒绝机制。

确认经验只表示允许记录到开发 Brain；建议变更 Harness 行为仍需独立提案、实施和效果验证。本轮没有自动或手动应用这些建议到 Harness 的功能，不能把保存报告称为自进化已完成。

### 存储与边界

- 配置、预览、任务、处理指纹和队列保存在 Harness 状态目录的 `ai-curation-dev/`，不在 Git 或 Brain 中。默认状态目录为 `~/.local/state/mick-harness`；遵循既有状态目录配置。
- 密钥所在目录权限 0700、配置文件 0600；不是系统钥匙串加密。其他同账户程序仍可能读取。前端不回显密钥，不写浏览器存储。
- 仅允许 `https://api.deepseek.com` 或其 `/v1` 官方入口，不跟随重定向、不继承环境代理；自定义网关暂不支持。
- 始终验证 HTTPS 证书与主机名。macOS 的 Python 默认信任库为空且未显式设置证书路径时，加载系统自带 `/etc/ssl/cert.pem`；不下载或信任服务端自签证书、不关闭校验。证书失败会单独提示，不再当作超时或 Key 无效。
- 运行状态持久化，页面自动查询。失败或中断不自动重试付费请求；重复提交同一预览返回原任务。生成可读报告后标记该输入已生成报告以避免重复付费；这不代表人工认可或已写入 Brain。
- 返回正文在解释前保存到私有任务记录，经过密钥及常见敏感信息脱敏；不在日志中输出。诊断区显示模型请求/报告整理阶段及错误码。已有两次历史失败未保存正文，无法恢复；不会为补诊断自动重新调用模型。
- 缺少引用或引用无法匹配时保留草稿并显示具体提示，不再整份拒绝；引用重复及未逐条覆盖全部输入不算错误。返回不完整时保留部分草稿及用量，但不标记输入为已成功处理，保存时需要额外核实确认。
- 审阅草稿按修订号防止覆盖别处修改；确认写入前检查来源是否已更正/撤回。确认保存后保留不可变审核版本，重复保存幂等。Brain 写入失败可重试本地保存，不重新调用模型。
- 开发 Brain 位于 `ai-curation-dev/brain/projects/<项目>/learnings.md`，仅接收人工确认的项目级经验；原始来源不删除、不覆盖。报告正文与输入来源一起追溯，不能据此声称所有输入都被报告采用。正式发布时的审批、跨项目提升及远端同步仍未开放。
- 每日请求限制包含连接测试，按 UTC 日界统计；记录服务返回的 token 用量，费用以供应商账单为准。
- 一次整理只调用一次模型。预览显示完整记录数、字符数（不是精确 token 数）及 16384 tokens 输出预算；实际按返回用量计费。真实上下文容量由模型接口校验，超限或输出不完整时明确失败，不自动截断、拆批或重试。整理请求超时为 120 秒，连接测试仍为 45 秒。
- 更新后的首次整理需要重新预览；旧分批/旧报告目标的预览被拒绝。新增整理范围、修改或撤回来源后也需重新确认，不在确认后悄悄附加记录。重新提炼固定原报告的来源集合，不包含后来新增记录。
- 来源变更、预览过期、配置变更或证据无效时拦截提交。模型结论只是候选，并不代表根因已确认或修复已验证。
- Harness 规则改进与报告沉淀分开：只有显式核实并“确认采纳”才批准开发试用建议并生成执行说明，不自动修改规则或迁移到生产。
