# 会话上报：开关、关联与触发记录

这是工作台设置中的独立能力，不是新的 Brain 同步器，也不是自动修改规则的入口。
需要部署同一版本的 Observer 和 Hook 适配器后，才会影响日常会话。使用 `harness update` 更新已安装的 Harness；只更新网页不能获得新的触发诊断。

## 用户可以做什么

进入 **设置 → 会话上报**：

1. **暂停／开启全局上报**：仅保存这一项设置，不提交 Git、不推送、不审批候选。
2. **设置单个项目**：跟随全局、项目开启、项目暂停。全局暂停是总开关，项目开启不能绕过它。
3. **关联未识别的会话工作区**：选择一个有效、已登记的项目。只改变后续事件归属，不移动文件、不搬迁历史，也不自动开启上报。可以移除指定关联。
4. **查看实际触发记录**：默认展示时间、Agent、事件、项目与结果；展开查看原因与耗时。可以手动刷新。页面约每 5 秒检查一次；用户操作表单、查看展开记录或页面在后台时暂缓自动刷新。

不存在配置时沿用已有上报行为，默认开启；这不代表本机 Hook 已获得宿主信任或当前会话已经加载。配置损坏时安全停报，页面显示错误，不擅自覆盖损坏配置或恢复开启。

## 开关到底控制什么

| 范围 | 是否受会话上报开关控制 |
| --- | --- |
| Harness 的 Codex／Claude 会话开始、回合开始、回合完成、会话结束事件 | 是 |
| Agent 通过 Harness 回写的工作回合、决策、交接事件 | 是 |
| Observer 扫描项目文件并汇总进度 | 否 |
| Brain 写入、候选审批、远端同步 | 否，沿用各自设置；已产生的项目事实仍可能按原规则进入 Brain |
| 用户自行安装的第三方 Hook、旧版 Brain 同步 Hook | 否 |
| 历史记录 | 保留，不删除 |

暂停期间，新的受控事件不发送，也不加入待处理队列。暂停前已排队的事件保留，暂停时不重放，恢复后可以继续重放。开关是运行时检查：已被接收端接受的在途请求不追溯撤销；服务端与客户端均检查策略，旧客户端通过新服务端写入时也受约束。旧适配器的离线直写不具备本功能，必须一起升级。

暂停后仍保留一条最小的本地触发诊断，用来解释“这次被开关跳过了”。这不是删除历史或“机器不再发生任何写入”的开关。

## 哪些内容会被记录、发到哪里

触发诊断只留在本机 Harness 状态目录的 `session-reporting/` 下：

- `configuration.json`：全局开关、项目覆盖、工作区与项目的显式映射及配置修订号。
- `records.json`：最近 500 次适配器触发的时间、事件类型、平台、项目标识、工作区路径、结果、固定原因、耗时。超出上限仅淘汰最早的诊断，不删除项目历史。
- `turns.json`：用于 Claude 回合关联的不可读随机标识；会话结束会清除关联，最多保留 1,000 个关联项。

目录与 Observer 一致：优先使用 `MICK_HARNESS_STATE_DIR`，否则使用 `$XDG_STATE_HOME/mick-harness`，未设置时为 `~/.local/state/mick-harness`。新增文件按仅当前用户可读写的权限创建，修改使用文件锁与原子替换。

**诊断不保存 Prompt、聊天正文、回复全文、工具参数、原始 session/turn 标识、完整错误堆栈，也不读取 transcript 文件。** 工作目录可能包含项目名称，会在这个本地界面展示；常见密钥模式会被隐藏。诊断自身不进入 Brain、不自动上传 Git。

原有项目事件仍写入项目的运行账本，并按原有 Brain 设置处理；其摘要、任务引用和来源规则没有被这个页面改写。不要把“诊断不上传”理解为“整个 Harness 不再同步”。

## 如何理解结果

| 页面结果 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 服务已接收并写入 | 本地 Observer 返回成功；重复事件去重 | Brain 已同步、每次都新增记录 |
| 已本地写入 | 服务暂不可用，已通过现有回退写入项目账本 | 远端同步成功 |
| 已跳过 | 适配器运行了，但因开关、目录未关联、输入不完整等原因没有执行上报 | Hook 从未触发 |
| 执行失败 | 适配器遇到错误，未证明服务接收成功 | 可以忽略失败或继续显示健康 |
| 尚未观察到 | 当前保留窗口内没有记录 | 当前宿主已信任 Hook 或服务健康 |

只有升级后的适配器被宿主实际调用，才会出现触发记录。它不尝试绕过 Codex／Claude 自身的 Hook 加载或信任机制。没有宿主触发时，工作台不能凭配置文件存在就声称“已生效”。

Claude 的回合事件不保证提供 `turn_id`，适配器在收到 UserPromptSubmit 时创建本地随机回合标识，Stop 关联到这轮；重复 Stop 不会生成多个完成事件。没有可关联的开始事件时，明确记录“缺少回合标识”，不伪造一轮任务。

## 安全与并发

配置接口只接受本机来源、JSON、服务端动作凭据和限定字段。更新必须携带当前修订号；另一窗口已修改时拒绝覆盖，请刷新后再做选择。接口不包含任意命令、任意文件写入、Git 提交、Git 推送或宿主权限修改能力。

只读接口：`GET /api/reporting.json`。配置接口：`POST /api/reporting/configuration`，动作分别为 `global`、`project`、`associate`。不要将本地服务暴露到公网；动作凭据不是面向公网的账户系统。

## 本次验证范围

- 专项合同：`python3 -B -m unittest discover -s tests -p 'test_harness_reporting.py' -q`。
- 现有 Observer 回归：`python3 -B -m unittest discover -s tests -p 'test_harness_observe.py' -q`。
- 测试仅使用临时项目、状态目录、Brain 和随机本地端口；不对真实项目做审批、上报设置变更、规则应用、Git 操作或部署。

候选提交 → 批准／驳回 → 应用规则 → 本地 Git 提交 → 远端推送，是另一个待开发里程碑。现有“批准”或“登记已落地”不应被理解为本功能已经完成了规则应用。
