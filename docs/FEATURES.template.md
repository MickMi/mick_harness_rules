# 功能清单 (Feature Inventory)

> 从用户体验视角记录“产品现在有哪些可见能力”。本文件不是 bug backlog、不是实现计划、不是技术架构说明。

## 状态口径

- **成熟**: 用户可稳定发现、理解并完成该功能的主要路径。
- **需调整**: 用户已经能看到或使用，但交互、入口、表达、完整性或稳定性仍需要打磨。
- **缺失**: 从产品目标看应该存在，但当前用户还看不到明确入口或完整闭环。

## 维护原则

- 只写用户能看到、点击、输入、切换、配置、感知到的功能。
- 不写隐藏逻辑、实现细节、内部脚本、权限绕行、构建方式、技术债或 bug 修复过程。
- 如果某项其实是问题，先把它翻译成“用户可见能力缺口”再写入；具体 bug 放 issue / TODO / plan.md。
- 每个功能只描述当前业务状态，不承诺实现方案。
