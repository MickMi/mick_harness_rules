# 功能清单 (Feature Inventory)

> 从用户体验视角记录 Mick Harness 当前可见能力；实现计划和技术细节仍以 `plan.md` 与架构文档为准。

## 状态口径

- **成熟**：用户可稳定发现、理解并完成该功能的主要路径。
- **需调整**：用户已经能看到或使用，但入口、完整性或不同 Agent 的一致性仍需打磨。
- **缺失**：从产品目标看应该存在，但当前还没有明确入口或完整闭环。

## 功能清单

| 状态 | 用户可见功能 | 用户入口 / 场景 | 备注 |
|---|---|---|---|
| 成熟 | 将统一 Harness 规则注入项目 | 在项目目录运行 `harness init` | 项目会同时进入本机项目注册表。 |
| 成熟 | 将 Harness Loader 注入支持的 AI Agent | `harness agents sync` 或 `harness export` | 不同 Agent 读取同一套目标、验证和交接纪律。 |
| 成熟 | 本机常驻工作服务器 | 安装 Harness 后访问 `127.0.0.1:6425` | macOS 用户级服务自动启动和保活。 |
| 成熟 | 所有已注入项目的统一总览 | 6425 工作台“所有项目” | 集中查看项目阶段、需求进度、阻塞和最近工作。 |
| 成熟 | 项目、版本、需求三层目标 | 从总览进入任一项目 | 项目目标来自 `docs/PROJECT.md`，当前版本来自 `docs/VERSIONS.md`，Plan 下沉为技术记录。 |
| 需调整 | Agent lifecycle 自动回写 | 启用对应 Agent Hook 后自动出现 | Codex 已有适配器；其他 Agent 取决于各自 Hook 能力。 |
| 需调整 | 角色工作、决策和交接回写 | 注入规则调用 `harness observe emit` | 已有真实事件和离线降级，但仍受 Agent 是否遵守注入规则影响。 |
| 成熟 | 五角色办公室与动态流转 | 项目首页点击 PM / 设计 / 开发 / 测试 / Review | 状态来自真实工作事件；真实交接和建议接手分别显示，当前来源与目标高亮。 |
| 成熟 | 角色执行详情 | 点击办公室中的角色 | 集中查看需求上下文、关联决策、执行记录和已登记交付物，不再拆成重复首页模块。 |
| 成熟 | 进度与角色历史跨刷新、重启保留 | 刷新工作台或重启本地服务 | 数据保存在项目事件账本，可确定性重放。 |
| 成熟 | 项目产物集中阅读 | 项目页“产物” | 已登记 Markdown 直接渲染；代码以可折叠、带行号的滚动块展示，并限制路径、类型和大小。 |
| 成熟 | 可追踪产物阶段导航 | AI 使用“版本 · 实际沟通日期 · 阶段标题”，用户在 Markdown 左侧选择阶段 | Observer 只解析标题并按行号定位正文；工作事件不再冒充内容索引，正文日期不会产生入口。 |
| 兼容 | 旧项目阶段标题 | 打开含“阶段名称（日期）”或“阶段名称 — 日期”的 Markdown | 允许导航并保留多个更新时间，但明确显示“未标版本 · 旧格式”，不推断缺失字段。 |
| 需调整 | 历史产物全文 | 产物阶段记录 | 当前只保存阶段摘要并读取现有文件，不保存每次修改前的完整正文快照。 |
| 成熟 | PM 版本路线 | 项目页“版本规划”与 `docs/VERSIONS.md` | 展示每个版本的目标、需求归属、迁移和完成状态。 |
| 成熟 | 真实 Git 状态的非技术视图 | 项目页“版本规划” | 只读显示当前分支、本地分支、Tag、HEAD 和未提交改动，不执行 Git 写操作。 |
| 缺失 | 跨机器或团队共享工作台 | 远程访问、多用户协作 | 当前刻意限制为 localhost 单用户产品。 |
| 缺失 | 自动创建、调度和审批 Agent | 多 Agent 自动编排 | 当前只记录真实工作，不替用户执行高风险调度或审批。 |
