# Harness 通用命令合同

> v0.21.0 · 2026-08-24 · 命令合同与安全基线

## 这套入口解决什么

Harness 把“建立计划、维护长期目标、配置 Brain、推进单条需求”收敛到四个稳定 CLI。CLI 是唯一事实源；Codex、Claude Code 等宿主只提供薄适配，不各自复制扫描、写入或门禁逻辑。

Harness 默认使用 `auto`，自动选择足以证明结果的最轻流程。用户平时不需要先输入模式命令：明确、可恢复、低风险且验证路径清楚的任务进入 `quick`，直接执行并做一次充分验证；普通多文件工作进入 `standard`；只有完整需求才进入 `e2e`。模式只控制交互强度，不降低先读后改、危险操作确认、撞墙熔断和完成验证。

`quick` 不创建 plan、不启动角色流、不展示 Self-Test 或六槽回合卡片。发现范围扩大、原意不清或需要高风险操作时，Harness 必须先说明原因，不能静默增加流程；从 `standard` 升级为 `e2e` 必须由用户确认。

| 用户意图 | 稳定入口 | 默认行为 | 明确写入 |
| --- | --- | --- | --- |
| 扫描项目并建立计划 | `harness plan` | 展示事实、冲突和拟写内容 | `harness plan --apply` |
| 建立或修订长期目标 | `harness goal` | 展示当前目标和拟议变化 | `harness goal --set "…" --apply` |
| 配置与检查 Brain | `harness brain` | 显示模式、位置、范围和连接状态 | `configure --apply`、`install` 或 `sync` |
| 完成一条需求的交付流程 | `harness e2e --requirement <id>` | 显示当前门禁、缺失证据和下一步 | 增加 `--run` 后才推进可安全自动化的阶段 |

所有命令都遵守同一条规则：先预览，再显式写入；预览失败不会留下半成品。

## 工作台操作

首页“Harness 操作 → 通用命令”提供同一套四个入口。用户先选择已连接项目或 Brain 模式，服务端再用固定参数列表调用 CLI 生成预览；确认单同时展示目标、读取范围、写入位置、实际命令预览和恢复说明。只有持有 localhost action token 且再次点击确认才进入后台执行，不接受自由命令或 Shell 字符串。

每次预览与执行都有操作编号和审计记录。结果区分“已完成 / 已安全停止 / 已取消 / 失败”，最近操作可重新打开查看执行前预览与脱敏后的结果；离开页面不会丢失后台状态。退出码 2 会记录为可恢复的“已安全停止”，不会伪装成系统故障。

## 宿主命令边界

Codex 已有 `/plan` 和 `/goal`。Harness 不覆盖、不伪装这两个原生命令，也不要求用户记住一套冲突的斜杠语义。Codex 中使用 `$harness-plan`、`$harness-goal`、`$harness-brain`、`$harness-e2e`；没有 Skill 入口时，直接使用稳定 CLI。

“通用”指意图、状态源、写入结果和验证合同一致，不表示每个 Code Agent 都必须支持相同的 `/` 语法。

## 四类命令的用户合同

### Plan

- 读取项目规则、现有 `plan.md`、项目目标、版本规划与 Git 工作区事实。
- 默认只展示扫描结果、当前活跃计划、冲突和拟写内容。
- `--apply` 只写 `plan.md`；发现无关的活跃计划时停止，不静默覆盖。
- 不修改代码、不切换分支、不发布版本。

### Goal

- 长期目标面向人类，描述项目持续服务的价值，不是当前版本目标、技术方案或任务清单。
- 默认展示 `docs/PROJECT.md` 的现有目标以及与版本计划的潜在冲突。
- 只有同时提供 `--set` 与 `--apply` 才更新 `docs/PROJECT.md`。
- 不把 `plan.md` 的阶段目标自动提升为项目长期目标。

### Brain

Brain 是可选服务，支持三种明确状态：

- `local`：只写本机，不存在远端同步待办。
- `remote`：本机仍是写入事实源，并连接用户明确配置的私有远端。
- `disabled`：不创建 Brain 目录，也不生成待同步状态。

普通 `harness init` 不创建 Brain。只有用户显式配置 `local` / `remote`，或执行要求完整服务的安装流程时，才建立本地骨架。状态页必须说明“读什么、写到哪里、什么会同步、什么需要审批”，不能只显示一个抽象的“已连接”。

公开 Harness 仓库内的旧版 `.brain-config.yaml` 只用于兼容已经存在本地 Brain 的老用户；新用户本机没有对应 Brain 目录时，不继承其中的作者远端，状态保持 `disabled`，也不会创建目录或产生待同步记录。显式提供迁移配置仍可读取旧格式。

项目事实可以自动沉淀到项目域；跨项目偏好、复用经验与 Profile 变化进入审批；Prompt、聊天全文、密钥、环境变量和完整日志不进入命令事件或远端同步。

### E2E

- 必须提供一个确定的 `requirement_id`，一次只处理一条需求。
- 第一轮先说明对目标、范围、关键假设、验收方式和执行路径的理解；用户确认后，产品审查、开发、独立 QA 和发布准备可以自主流转，不按角色机械打断用户。
- 默认只诊断。`--run` 在已确认意图内自主推进；出现新的产品决策、方向变化或高风险操作时才暂停并解释。
- 最远到达“发布候选”；不会自动 merge、push、tag、deploy 或 publish。

## 统一错误语义

| 退出码 | 含义 |
| --- | --- |
| `0` | 预览或操作成功 |
| `2` | 可恢复冲突或前置条件不足，操作已安全停止 |
| `64` | 输入缺失或无效 |
| `69` | 所需本地服务、宿主能力或远端不可用 |
| `74` | 无法安全读取或写入目标文件 |

错误输出必须包含：停止原因、未发生的写入、用户下一步。不得用“应该成功”代替真实状态。

## v0.20.1 基线

v0.21 开工前的可复现基线：

- 全仓回归：142 项测试通过。
- Codex 全局 Loader：13,646 bytes。
- 项目 Loader：18,994 bytes。
- 两者合计：32,640 bytes；距离默认 32 KiB 指令发现上限只剩 128 bytes。
- 完整 `rules/extended.md` 为 43,831 bytes，必须继续按需加载，不能并入日常上下文。

这些数字是瘦身前基线，不是未来目标。v0.21 会增加自动预算检查，确保 Kernel 仍可发现的同时显著留出空间。

## v0.21 常驻上下文预算

`scripts/harness-context-budget.py` 对四个边界做确定性检查：Core 不超过 10 KiB、项目 Loader 不超过 16 KiB、Codex 全局导出不超过 12 KiB、两份常驻入口合计不超过 28 KiB。同时逐项确认“先读后改、plan 检查、验证 Gate、Debug Card、回合卡片、按需 Extended”仍存在，避免只追求文件变小。

当前 v0.21 预算以“4 KiB 个人 Capsule 已用满”的最坏常规输入生成项目 Loader，再与 Codex 全局导出合并测量；结果由检查器实时给出，不依赖仓库里预先存在的 `dist/`。相比 v0.20.1 的 32,640 bytes 基线显著降低。近似 Token 统一按 4 bytes/token 展示；实际模型 Token 会受中英文、分词器和宿主额外指令影响，因此工作台只把它显示为估算，不冒充账单数据。

个人 Agent Capsule 最多注入 4 KiB；超过时按 UTF-8 安全截断，并保留源文件按需读取提示。角色细节、产品逻辑、PRD、设计与四类命令操作均留在 Skill / reference 中，需要时再加载，不并入日常 Loader。

## 事实源

机器可读合同位于 `config/command-registry.json`。CLI、Skill、工作台和测试都应读取或验证这一合同；本文是给用户阅读的解释，不是第二套实现。
