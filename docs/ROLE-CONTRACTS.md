# 角色契约与行为评测

> 适用版本：v0.17.0
> 原则：文档结构合格、真实 Agent 执行合格是两种不同证据。

## 标准角色

| 角色 | 负责 | 不负责 | 最小交付 |
|---|---|---|---|
| PM | 用户目标、需求边界、版本归属和产品验收 | 技术方案与代码实现 | 产品共识、版本归属、验收边界 |
| Planner | 把锁定需求拆成有依赖、有验证的执行计划 | 发明产品范围 | 文件级步骤、风险、验证与停止条件 |
| Executor | 按已确认范围实现并提供当次验证 | 改写目标或用实现替代验收 | 改动、验证证据、剩余风险 |
| QA | 用用户路径、边界、失败态和真实状态源找缺陷 | 自行定义产品行为 | 测试结果、复现证据、未覆盖风险 |
| Reviewer | 开发前审查产品逻辑；高风险发布前审查正确性、安全、兼容性和证据充分性 | 替 PM 裁决产品范围或替 QA 执行完整验收 | 按严重度排序的发现与结构化门禁结论 |

Designer 是可选角色，只在视觉层级、交互或设计质量显著影响需求时进入；它不接管 PM、Planner 或 Harness 权限。

角色与 Skill 是“职责合同”和“专业方法”的关系：Designer 规定何时进入、读取什么、负责什么、如何验收和交给谁；Harness 内置的 `designer-craft` 提供信息层级、交互、视觉、状态与可访问性的具体工作方法，仅在真实设计任务中按需加载。外部开源 Skill 只作为经过来源、许可证和安全审查的上游参考，用于维护内置 Skill；运行时不临时下载、不要求项目安装，也不能覆盖角色边界、Harness 权限或完成定义。

## 七段契约

每个角色文件只保留七个二级章节：`触发 / 必读输入 / 职责 / 非职责 / 交付物 / 验收 / 交接`。结构测试检查章节、长度、旧冲突规则和供应商绑定；它只证明规则可加载、边界可读。

行为用例位于 `tests/fixtures/role-behaviors.json`。PM、Planner、Executor、QA、Reviewer 各有至少 3 个正向用例和 2 个越界/回流用例；Designer 作为可选角色，只记录越权/误激活的边界用例，不做完整正向行为评测。静态测试不会生成虚假的 Agent 答案。

## 真实样本评分卡

每个 Agent、每个角色按同一任务保存一个脱敏结果摘要，五项各 0–2 分：

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 加载 | 无规则证据 | 只发现 Loader/Hook | session 回报当前规则版本与角色 digest |
| 职责 | 越权或漏掉核心职责 | 基本完成但边界含混 | 完成职责且正确回流越界事项 |
| 交付 | 无可复用结果 | 有结果但缺关键字段 | 交付结构完整且能被下一角色使用 |
| 验证 | 无证据或把推断当事实 | 有部分检查 | 证据直接支持声明并标明未验证项 |
| 交接 | 无下一步或错误流转 | 给出模糊下一步 | 明确接手角色、输入和完成条件 |

- 总分 8–10 且没有任何 0 分：真实样本合格。
- 总分 5–7：需要调整角色规则或用例。
- 总分 0–4，或任一安全/隐私越界：不合格。
- 同一任务的 Claude Code 与 Codex 分开记录，不能互相代替。

## 隐私与保存

真实评测只保存任务类型、规则版本、角色 digest、五项分数、问题摘要和证据引用；不保存 Prompt、回复全文、transcript、密钥、环境变量或 Brain 私人正文。任何外部请求、付费模型调用或真实全局配置修改均先获得用户授权。
