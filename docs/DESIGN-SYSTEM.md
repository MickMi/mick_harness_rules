# Harness · 紧凑操作界面标准

## 2026-09-09 · 从操作任务建立层级

用于 Harness 工作台的默认参考，不是所有注入项目的强制视觉风格。已有项目设计系统优先；按需阅读，不加入全局 Prompt。

参考 [shadcn/ui](https://github.com/shadcn-ui/ui)、其[官方 Dashboard](https://ui.shadcn.com/examples/dashboard)和[按钮规范](https://ui.shadcn.com/docs/components/base/button)。借鉴统一的尺寸、主次操作与布局节奏，**不安装 React/Tailwind、不复制整套模板**。上游是 MIT 开源；本页数值是 Harness 的适配决定，不声称为上游原值。

| 元素 | 默认标准 |
|---|---|
| 页面标题 / 区块标题 / 正文 / 辅助 | 28 / 17 / 14 / 12–13px |
| 按钮 | 桌面至少 32px 高，13px 文字，6px 圆角，6×10px 内边距 |
| 触屏 | 可操作目标至少 44px，不用缩小字号解决空间问题 |
| 间距 | 4px 基础倍数；区块 16–20px，相关控件 8–12px |
| 色彩 | 中性背景和边框；一种强调色；警告/危险只表达真实状态 |

每个任务区域突出一个下一步；编辑、纠错、危险操作放入详情，不并列一排同等重要的按钮。不要把导航、状态标签、按钮全做成圆角胶囊。标题不能继承按钮字号，长名称必须换行，动作不能超出容器。

## 信息与操作

- 设置顺序：同步清单 → 需要人审批的内容 → 项目摘要 → 原始记录和高级设置。
- 默认给结论、明确状态和下一步；来源、路径、执行日志在可展开详情中。
- 无待审批内容只显示短空态，不占据大块卡片。
- 一次点击一个动作：整理、保存候选、送审、批准、实施、同步互不冒充。
- 页面称“已验证”需要真实证据；用户登记的状态须明确标注为登记。

## 必须留证的检查

桌面与 390px 窄屏各检查一次；200% 缩放可操作；长中英文、空/错误/禁用/加载态不溢出。实际点击主路径并刷新核对。自动检查按钮字号和尺寸、页面横向溢出、摘要来源与状态；无模拟数据进入真实 Brain。

## 项目记忆不是待办队列

本机摘要读取全部记录，按明确项目/任务归组，提取最新结论；任务无关的过程日志留在原始记录。不会按关键词猜“根因/修复成功”，也不向外部模型发送私人内容。

同一任务三条证据不等于三次问题。提炼候选需要用户填写可复用的问题和改进方向，来源随候选保存；已有候选可回看处理状态。此版不替用户进行跨主题语义归纳，不自动批准、写规则或声称问题已解决。
